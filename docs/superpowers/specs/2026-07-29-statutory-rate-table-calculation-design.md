# 法定税率表计算规则设计

## 目标

将全国统一、能够从官方法律文件中确定的税目税率变成可审计的机器规则，首个正式落地对象为 2023—2026 年印花税。客户不再手工输入全国统一税率；系统根据客户确认并绑定证据的税目自动选择税率。地方决定的税率、优惠资格和无法从全国规则唯一确定的参数仍保持显式缺口，不作推测。

## 范围

本阶段包括：

- 为税务规则包增加严格的 `1.3.0` schema；
- 允许同一税种的 screening 与 calculation 包在相同期间并存，并在一次检查中按成熟度分阶段执行；
- 支持“税基 × 法定税率表匹配结果”的计算；
- 提供覆盖《中华人民共和国印花税法》税目税率表的正式计算包；
- 在机器快照和中文《税务健康检查报告》中保留税目、税率、公式、金额和官方来源；
- 对税目缺失、未知税目、未确认事实和证据不足稳定返回缺口或阻断结果。

本阶段不包括：

- 自动判断合同在法律上属于哪个印花税税目；
- 自动套用小微企业减半等主体优惠；
- 将证券交易税率的期间调整错误地推广到普通企业凭证；
- 把契税 3%—5% 的法定幅度当作具体地方适用税率；
- 猜测任何省级、地市级政策。

## 方案比较

### 方案 A：通用法定税率表（采用）

在规则包中声明税目选择事实和税率表，核心 evaluator 进行严格匹配。优点是税率、来源和期间都留在版本化规则包中，可复用于消费税、车船税等存在分类税率的税种；缺点是需要新增 schema。

### 方案 B：印花税专用 evaluator

把税目和税率直接写进 Python。实现较快，但法律内容与代码耦合，后续更新和审计困难，也无法复用于其他税种。

### 方案 C：继续要求客户确认税率

保持 `calc.rate` 参数化模板。兼容性最好，但没有真正实现全国统一法定税率，客户仍可能输入错误税率，不满足正式规则包目标。

## 数据模型

`CalculationSpec` 增加可选 `rate_table`，其结构为：

- `selector_fact_key`：已确认的税目代码事实；
- `entries`：非空、税目代码唯一的 `(selector, rate)` 列表；
- 每个 `rate` 为大于等于 0 且不超过 1 的十进制字符串；
- `rate_fact_key` 与 `rate_table` 二选一，不能同时出现；
- `deductions_fact_key` 只允许用于明确支持扣除额的公式。

schema `1.3.0` 保持 `1.0.0`—`1.2.0` 的向后读取兼容。`1.3.0` 只允许计算成熟度规则包，并继续要求完整官方来源元数据。

registry 只禁止同一税种、同一地区、同一成熟度的正式包发生期间重叠。screening 与 calculation 包允许覆盖同一期间，因为二者属于先后阶段，不是竞争候选。`select_pack_segments` 增加明确的成熟度过滤参数，调用方不得把不同成熟度混在一次选择中。

## 计算流程

1. 只选择 screening 成熟度规则包并完成适用性判断。
2. 全部适用性事实为否时直接返回不适用，不提出计算问题。
3. 任一适用性事实为真时，选择覆盖同一期间的 calculation 成熟度规则包；不存在时保持 `calculation_rule_unavailable`。
4. 检查税基与税目选择事实是否存在、是否由客户确认、是否绑定证据。
5. 用税目代码对税率表进行精确匹配；不做模糊匹配或 AI 分类。
6. 未知税目返回 `unknown_statutory_rate_selector`，不得回退到客户输入税率。
7. 使用精确十进制运算计算金额，按人民币分四舍五入。
8. `CalculationRecord` 记录税目选择值、选定税率、税基、扣除额、净税基、金额和证据。
9. 中文报告显示中文税目名称；机器快照保留稳定税目代码。

内置 bundle 同时加载 screening 与 calculation 包。问题目录增加税基和印花税税目的中文问题，使 Codex、Hermes、WorkBuddy、扣子、Qoder、Claude Code 和 OpenClaw 都沿用现有共同任务合同提问。

为保持 `1.2.0` 显式计算包兼容，调用方只提供 calculation 包且没有 screening 包时，协调器直接执行 calculation 阶段；只有内置两阶段 bundle 才要求先完成适用性判断。

## 印花税正式包

税率表覆盖《中华人民共和国印花税法》附件列明的合同、产权转移书据、营业账簿和证券交易税目。税目代码保持稳定英文标识，客户问题和报告使用中文标签。

证券交易税率存在期间政策调整风险，因此正式包按有效期间切分；无法逐段核验的期间不得被一个统一税率覆盖。主体优惠不直接写入基础税率，未提供已确认优惠资格及对应官方规则时，报告明确提示“未计入优惠”。

## 契税边界

契税继续使用参数化计算包。全国法律只能确定 3%—5% 幅度，具体税率由省级决定；系统必须要求与不动产所在地、交易日期相匹配的地方政策证据。法定幅度可以用于输入校验，但不能自动选择具体税率。

## 错误与安全边界

- 重复税目代码、非法十进制税率、空税率表：`invalid_calculation_spec`；
- 税目事实不是字符串或未确认：`invalid_rate_selector_fact` 或确认缺口；
- 未知税目代码：`unknown_statutory_rate_selector`；
- 无证据：`missing_calculation_evidence`；
- 规则期间不完整：保持 `blocked`，不得推断邻近期间规则；
- 客户输入和报告不得暴露内部 evaluator ID。

## 测试与验收

- 模型和 manifest 严格解析测试；
- `1.2.0` 向后兼容测试；
- 同成熟度重叠拒绝、跨成熟度重叠允许及分阶段选择测试；
- 适用性为否时不提出计算问题，适用性为真时进入正式计算包；
- 税率表重复、非法税率、互斥字段和未知税目测试；
- 印花税全部税目逐项税率测试；
- 已确认税基和税目产生可审计金额；
- observed/inferred 或无证据事实不能计算；
- 契税仍要求地方税率，不从 3%—5% 中任选；
- 中文报告显示税目和金额，机器快照保留代码；
- 全量测试、构建、严格发布校验和已安装 wheel 验证通过。
