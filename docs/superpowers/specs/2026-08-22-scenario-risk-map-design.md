# OpenTaxCheck 经营场景税务风险地图设计

## 目标

为 OpenTaxCheck 增加一套由 Skill 对话和客户 PDF 共用的经营场景目录。客户从熟悉的经营活动理解检查范围，确定性引擎仍按税种、检查编号、证据和规则版本运行。

本设计只整理并呈现已经存在的检查能力。外部文章或其他清单中的检查点，在法规、公式、证据和测试完成前，只能登记为询问型候选，不得成为自动税务结论。

## 范围

本轮同时改进：

1. Skill 的开场引导、经营事实追问和动态资料清单；
2. 正式中文 PDF 的“本次税务检查地图”；
3. 两者共用的机器可读场景目录和覆盖状态统计。

本轮不增加未经核验的税务计算规则，不建设独立前端，不改变正式交付仅提供中文 PDF 的边界。

## 场景模型

第一版采用五类客户可理解的经营场景：

1. 收入与流转；
2. 成本费用；
3. 资产与不动产；
4. 合同及特殊交易；
5. 人员、股东及关联事项。

每个场景条目至少包含：

- 稳定的场景标识；
- 中文名称和客户可理解的说明；
- 关联税费项目；
- 关联的稳定检查编号；
- 启用该场景所需的经营事实；
- 所需资料类别；
- 当前能力类型：确定性检查或询问型候选；
- 适用的规则或目录版本。

目录不能重复保存税率、计算公式或结论逻辑。税务计算仍由现有规则包负责，目录只负责导航、关联和呈现。

## 状态模型

每个检查点只能映射为以下客户可见状态之一：

- `executed_clear`：已执行，按当前资料和规则未发现异常；
- `executed_risk`：已执行，发现需关注事项；
- `awaiting_evidence`：待补资料或待客户确认；
- `received_unparsed`：资料已收到但尚未成功提取或结构化；
- `not_applicable`：根据已确认的经营事实不适用；
- `not_performed`：本次未执行。

统计规则如下：

- `skipped`、资料缺失、资料未解析和未执行都不得计入已执行或已通过；
- “未发现异常”只能描述当前资料、检查范围和规则版本下的结果，不能写成“无税务风险”；
- 场景汇总数字必须从案件的真实检查状态计算，不能由模板硬编码；
- Skill、PDF、机器快照和交付清单对同一案件修订必须使用同一份汇总结果。

## Skill 对话

首次对话保留现有企业名称、地区、主营业务、检查期间和增值税纳税人类型五项基础信息。随后仅询问能够决定场景是否展开的少量经营事实，例如是否持有或交易不动产、是否存在雇员与股东往来、是否发生关联交易。

对话遵循以下顺序：

1. 收集基础信息；
2. 识别可能相关的经营场景；
3. 展示基础资料清单；
4. 按已触发场景逐步展示建议资料和条件资料；
5. 资料进入案件后，根据当前覆盖状态继续追问。

场景命中只决定是否询问和索取资料，不等于认定某税种适用。AI 智能体不得选择税目、税率、科目分类、地方政策或税务结论，也不得替客户确认事实。

## PDF 检查地图

正式 PDF 在执行摘要之后、详细风险之前增加“本次税务检查地图”。该页面至少展示：

- 五类经营场景；
- 每类场景关联的检查点数量；
- 已执行且未发现异常的数量；
- 已执行且发现需关注事项的数量；
- 待补资料或确认的数量；
- 已收到待解析的数量；
- 不适用和未执行的数量；
- 对状态口径的简短说明。

如果某类场景没有关联检查点，仍可显示为零，但不能用空白暗示已经检查。长名称和大量检查点必须支持 A4 分页，不破坏现有目录、页码和字体。

## 数据流与职责

统一场景目录是静态产品元数据。运行时由独立汇总函数接收当前案件检查结果、资料覆盖矩阵和已确认经营事实，输出版本化的场景覆盖快照。

数据流为：

```text
统一场景目录
      +
案件检查结果、资料覆盖、已确认经营事实
      ↓
版本化场景覆盖快照
      ├── Skill 动态追问与资料清单
      └── PDF 检查地图与机器快照
```

目录层不得修改引擎结果。汇总失败时，正式 PDF 不得伪造零风险地图；应阻止发布并保留可诊断错误，沿用现有原子交付机制。

## 初始映射

第一版必须关联当前五项高频账税交叉检查：

- `BOOK-FS-REV-001`
- `FS-VAT-SALES-001`
- `BOOK-VAT-OUTPUT-001`
- `FS-CIT-REV-PROFIT-001`
- `BOOK-CIT-BE-001`

同时映射当前已有的20个税费项目筛查与正式计算路径。一个检查点可以关联多个场景，但总量统计必须按稳定检查编号去重，避免同一检查被重复计数。

## 测试与验收

采用测试驱动开发，至少覆盖：

1. 目录结构、标识唯一性和引用的检查编号有效；
2. 一个检查关联多个场景时，总量按检查编号去重；
3. 六种客户可见状态的确定性转换；
4. `skipped`、缺资料、未解析和未执行不计为通过；
5. 未触发场景不会生成冗余客户问题；
6. 已触发场景会生成对应资料任务；
7. Skill、快照和 PDF 对同一修订的统计一致；
8. PDF 包含五类场景、稳定检查编号和口径说明；
9. 长文本、零风险、大量资料缺口和无适用场景案例的 PDF 可正常分页；
10. 客户文本继续转义，PDF 渲染继续阻断外部网络；
11. 正式交付仍只提供中文 PDF，不回退 Word；
12. 现有借贷平衡、账税交叉检查和交付哈希绑定测试不回归。

完成后执行聚焦测试、完整回归、构建、严格发行验证、隔离 wheel 安装验证和逐页 PDF 视觉检查。

## 兼容与版本

场景目录和场景覆盖快照分别声明独立 schema 版本。新增字段优先以可选方式进入现有案件快照；正式客户报告 schema 是否升级，由实现计划根据当前兼容测试确定。

历史交付只读保留，不迁移旧报告，也不从旧结果反推经营事实。旧案件重新生成报告时，必须基于当前来源、当前案件修订和当前目录版本重新汇总。

## 安全与专业边界

- 借贷不平衡仍属于阻断项；
- AI 只负责资料理解、追问和解释；
- 未经客户确认的经营事实不能用于确定不适用；
- 未经核验的外部检查点不能变成正式规则；
- 所有客户可见结论继续绑定来源、期间、规则版本和证据状态；
- 报告继续声明其为税务健康自查材料，不是审计、鉴证、法律意见、申报结论或税务机关认定。
