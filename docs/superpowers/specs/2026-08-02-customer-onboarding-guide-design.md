# OpenTaxCheck 客户开场与分层引导设计

**日期：** 2026-08-02  
**状态：** 已确认设计，待实施  
**范围：** AI 智能体中的首次开场、企业基础信息收集、动态资料清单和案件阶段提示

## 1. 目标

OpenTaxCheck 已经能够接收客户资料、执行税务健康检查并生成中文交付物，但当前 Skill 偏向开发者操作说明，缺少统一的客户开场。不同 AI 智能体可能自行组织话术，造成资料要求不一致、首次使用门槛过高，或者遗漏隐私与检查边界。

本功能把“工程上可运行”进一步变成“普通企业负责人看得懂、愿意开始、知道下一步做什么”。客户不需要一次准备齐全部资料；系统先了解企业，再生成针对性资料清单，有多少资料先处理多少，缺口和矛盾通过后续中文对话补齐。

## 2. 设计原则

- 使用“AI 智能体”，不使用“宿主 Agent”“AI 宿主”等开发者术语。
- 采用两层表达：第一层简短、老板友好；第二层保留完整专业边界。
- 首次进入先收集企业基础信息，再生成适用资料清单。
- 资料不完整不阻止开始，但未确认事项必须持续可见。
- AI 负责自然沟通，Python 核心负责案件状态、字段、材料分组和不可省略的边界。
- 七个支持的 AI 智能体共用同一份结构化引导合同，不各自编造流程。
- 不把缺失资料、未覆盖程序或未确认事实改写为“无风险”。

## 3. 首次开场

首次进入且案件尚无企业基础信息时，AI 智能体展示以下第一层话术。允许在不改变事实和边界的前提下做轻微口语化调整，不得删除资料可渐进提供、隐私说明或输出名称。

> 您好，我是税务健康检查 AI 智能体。
>
> 我可以根据企业账套、财务报表、纳税申报表及相关业务资料，协助检查账务勾稽、申报一致性和常见税务风险，并最终生成中文《税务健康检查报告》，列明发现的问题、判断依据、待补资料和处理建议。
>
> 资料不需要一次准备齐，您手头有多少可以先提供多少。我会先形成初步检查结果；遇到资料缺失或内容矛盾时，再用简单问题逐项向您确认。
>
> 开始前，请一次告诉我以下信息，暂时不清楚的可以填写“不确定”：
>
> 1. 企业名称
> 2. 所在省市
> 3. 主营业务或行业
> 4. 希望检查的期间，建议为 2023–2026 年
> 5. 增值税纳税人类型：一般纳税人、小规模纳税人或不确定
>
> 您提供的资料由当前 AI 智能体协助处理。OpenTaxCheck 默认在本地运行，不会主动将客户资料上传给项目方；如需调用云端识别或企业查询服务，我会先说明发送内容并征得您的同意。

首次开场不直接列出全部 20 个税费项目，也不要求客户理解内部状态、规则包或技术字段。

## 4. 基础信息合同

第一轮一次请求以下五项信息，漏答或回答“不确定”时再逐项追问：

| 字段 | 必要性 | 用途 |
| --- | --- | --- |
| 企业名称 | 必填 | 绑定单一法律实体和报告名称 |
| 所在省市 | 必填 | 识别地方政策和地区资料需求 |
| 主营业务或行业 | 必填 | 生成适用税种与专项资料候选 |
| 检查期间 | 必填 | 选择规则期间；界面建议 2023–2026 年但允许客户提出其他期间 |
| 增值税纳税人类型 | 可回答“不确定” | 选择增值税路径；不允许 AI 猜测 |

企业名称、地区、主营业务和检查期间不完整时，引导状态保持为 `awaiting_business_profile`。纳税人类型不确定不阻止资料盘点，但相关计算保持待确认。

当前正式规则范围为 2023-01-01 至 2026-12-31。客户提出超出范围的期间时保留其原始请求，但案件进入 `blocked`，中文说明当前可覆盖区间并要求客户缩小期间或等待后续规则版本；不得静默截断检查期间。

## 5. 动态资料清单

收到基础信息后，Python 核心按优先级生成三组中文资料要求。AI 智能体不得把条件资料改写为所有企业都必须提供。

### 5.1 先提供这些，就可以开始

- 序时账或明细账 Excel；
- 科目余额表；
- 资产负债表、利润表、现金流量表；
- 已有的纳税申报表。

### 5.2 有的话建议一并提供

- 增值税申报表及附表；
- 企业所得税年度申报表；
- 发票汇总、固定资产清单、工资薪金资料；
- 已有的税务计算表或税务机关通知。

### 5.3 仅在涉及相关业务时提供

- 房屋、土地、车辆资料；
- 买卖、租赁、借款、股权转让等合同；
- 契税、印花税、房产税等申报或缴税资料；
- 进出口、资源开采、房地产开发等专项资料。

第三组由企业地区、行业、主营业务、已观察资料和已确认事实共同驱动。具体税种仍须由确定性适用性筛查确认，不能只凭行业关键词形成税务结论。

资料清单固定附带以下提示：

> 请尽量提供财务软件直接导出的原始文件，不必修改表头或重新整理；压缩包也可以。资料不完整不会阻止开始检查。

## 6. 状态化对话

引导不是一段永久重复的欢迎词。每次交互先读取案件状态，再返回当前阶段唯一需要客户关注的内容。

| 引导阶段 | 触发条件 | 客户侧主要动作 |
| --- | --- | --- |
| `welcome` | 尚未建立案件 | 了解能力并开始 |
| `awaiting_business_profile` | 基础信息缺失 | 一次提交五项基础信息或回答“不确定” |
| `awaiting_documents` | 已有企业信息但尚无可检查资料 | 按动态清单上传现有资料 |
| `inventory_in_progress` | 正在盘点资料 | 等待盘点完成，不重复上传 |
| `check_in_progress` | 已具备最低检查条件 | 等待勾稽、筛查和报告生成 |
| `awaiting_customer_input` | 存在资料缺口、矛盾或待确认事实 | 回答少量中文问题或补充资料 |
| `draft_report_ready` | 初版报告已生成但仍有未解决事项 | 查看初版报告或继续补齐 |
| `completed` | 当前可执行程序已完成 | 下载报告及交付物 |
| `blocked` | 文件安全、数据质量或处理错误阻断 | 按中文恢复指引处理具体问题 |

建议阶段话术：

- 收到资料：说明已收到的文件数量，接下来核对可读性、期间、借贷平衡和账表勾稽。
- 开始检查：说明资料不足项目会保留为待确认，不直接判断为无风险。
- 补件：每轮只展示少量关键问题，同时展示提问原因、可接受证据和“不清楚”的处理方式。
- 初版报告：明确剩余待补资料和待确认事项数量，允许先查看报告并继续更新。
- 完成：优先展示中文《税务健康检查报告》，再列出 Word、PDF、工作底稿和证据包等可用下载项。

客户中途退出后再次进入，系统从当前阶段继续，不重复首次欢迎词，不丢失已确认事实。

## 7. 第二层专业与隐私说明

客户查看详细说明、准备上传资料或系统准备调用联网服务时，展示完整边界：

> 本报告仅用于企业内部税务健康自查，不属于涉税鉴证、专业税务意见、纳税申报结论或税务机关认定。检查结论受客户提供资料、确认事实、适用期间及地方政策完整性的限制。

生成报告不要求税务专业人员签字、盖章或批准。系统必须如实保留未确认事项、未覆盖路径和资料限制。

“默认在本地运行”只描述 OpenTaxCheck 核心，不代表所有 AI 智能体都绝对离线。需要云 OCR、企业查询或其他远程服务时，调用前必须披露服务商、拟发送内容、用途、保存期限和风险，并取得明确授权。未经授权不得上传包含客户原始证据的证据包。

## 8. 统一引导合同

新增由 Python 核心生成的宿主无关客户引导：公共 API 使用 `build_case_guide(case_dir)`，CLI 使用 `opentaxcheck case-guide --case CASE`。客户档案通过 `start_case_from_profile(case_dir, profile)` 写入，CLI 使用 `opentaxcheck case-start --case CASE --profile profile.json`。这些名称属于本设计合同，实施时不得另行发明平行入口。

首次开场发生在案件初始化之前。AI 智能体取得五项基础信息后，将其提交为版本化的 `customer-profile/v1` 对象；Python 核心验证企业名称、地区和期间，并创建案件。客户档案包含 `schema_version`、`entity_name`、`province_city`、`primary_business`、`period_start`、`period_end` 和 `vat_taxpayer_type`；纳税人类型只接受 `general`、`small_scale` 或 `unknown`。验证后的档案保存在案件工作目录并进入审计轨迹，AI 智能体不得直接修改案件状态。

尚不存在案件或客户档案时返回 `welcome`；案件目录已建立但档案验证尚未完成时返回 `awaiting_business_profile`。两者不得随机选择。档案验证完成后才能进入 `awaiting_documents`。

返回对象至少包含：

```json
{
  "schema_version": "case-guide/v1",
  "stage": "awaiting_business_profile",
  "title_zh": "开始税务健康检查",
  "message_zh": "……",
  "profile_questions": [],
  "document_groups": [],
  "privacy_notice_zh": "……",
  "disclaimer_zh": "……",
  "available_actions": []
}
```

面向 AI 智能体的对象使用字段白名单和版本号。客户侧只展示中文标题、正文、问题、资料组和可执行动作；`stage`、schema 版本及内部标识保留在机器层。

Skill 的职责是读取并展示该合同、收集答案和调用现有案件接口。Skill 不自行推断阶段、不自行生成税种资料要求、不伪造已完成状态。

## 9. 错误与恢复

- 文件无法读取时，说明具体文件和可采取动作，不显示堆栈或内部错误码。
- 发现多个实体或期间冲突时，暂停税务判断，要求客户明确案件范围。
- 借贷不平衡、账表无法勾稽或申报资料矛盾时，保留阻断状态并解释需要核对的差异。
- 客户拒绝联网授权时，继续本地可执行流程，把无法执行的云端步骤记为限制。
- PDF 渲染器不可用时仍交付其他格式，并明确 PDF 暂不可用，不伪造文件。
- 任一阶段失败后继续使用当前不可变运行记录和案件快照恢复，不把旧成功结果当作当前结果。

## 10. 验收与测试

### 10.1 合同测试

- `case-guide/v1` 只允许规定字段和阶段；
- 七个宿主合同回放接收同一引导对象；
- 客户展示字段全部为中文且不包含内部状态码、事实键或规则包标识；
- “资料可渐进提供”、条件联网授权和免责声明属于不可删除字段。

### 10.2 状态测试

- 尚未建立案件时返回 `welcome`；已建立案件但客户档案验证未完成时返回 `awaiting_business_profile`；
- 基础信息齐全后进入 `awaiting_documents`；
- 纳税人类型为“不确定”时允许盘点，但相关判断保持待确认；
- 上传资料后不再重复欢迎词；
- 初版报告存在未解决事项时返回 `draft_report_ready`，不返回 `completed`；
- 中断后恢复到同一阶段。

### 10.3 内容测试

- 首次开场保持一屏内可读；
- 基础信息一次询问、漏项再逐项追问；
- 普通企业不被要求提供明显无关的契税、资源税或海关资料；
- 条件资料的触发可追溯至客户信息、已观察资料或已确认事实；
- 不出现“100% 准确”“没有资料也无风险”“所有处理绝对本地”等表述；
- 报告正式名称始终为《税务健康检查报告》。

### 10.4 端到端验收

在至少一个真实 Codex 项目级 Skill 环境中验证首次开场、基础信息、动态清单、资料上传、初版报告、补件和继续运行；七宿主离线回放验证同一合同。其他宿主只有真实运行后才能标记为 runtime verified。

## 11. 非目标

本阶段不实现独立网页后台、账号体系、收费、远程文件存储、电子签名或七个宿主的原生插件；不改变税务规则、计算公式和报告审批边界；不要求客户一次上传完整资料；不允许 AI 根据开场答案直接形成税务结论。
