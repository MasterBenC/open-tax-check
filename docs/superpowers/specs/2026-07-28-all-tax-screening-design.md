# 2023–2026 全税种筛查设计

## 背景

OpenTaxCheck 已具备客户自用《税务健康检查报告》的确定性基础框架：20 个税费项目注册表、版本化规则包选择、事实与确认、中文报告、问题合并和增量重跑。当前内置内容仍只有一个明确标记为 `prototype` 的增值税示例包，不能声称已经完成 2023–2026 年的实质税务筛查。

本阶段是已批准路线中的第二批：为中国现行 18 个税种，以及教育费附加、地方教育附加，共 20 个项目补齐 2023-01-01 至 2026-12-31 的全国适用性筛查、资料清单、中文客户问题和官方依据。本阶段不计算税额；计算与一致性规则留给后续第三批。

## 目标

- 20 个税费项目均有连续覆盖 2023–2026 年的全国 `screening` 规则包。
- 客户无需单独安装规则包；官方规则包随 OpenTaxCheck 一起安装和升级。
- 客户、宿主 Agent 和报告正文使用通俗中文，英文代码只用于机器接口与审计。
- 只有明确、可追溯的客户确认或资料证据才能支持“不适用”结论。
- 资料不足、地方政策缺失和事实冲突必须失败关闭，不得被解释为无风险或合规。
- 规则内容与核心引擎分离，使日常法规维护主要通过版本化规则数据完成。
- 为 Codex、Hermes、WorkBuddy、扣子、Qoder、Claude Code 和 OpenClaw 提供同一套确定性能力，不复制税务规则。

## 非目标

- 不计算应纳税额、滞纳金、罚款或申报调整额。
- 不实现第三方规则市场、远程规则下载、自动更新服务或规则包签名基础设施。
- 不把 GitHub 项目、模型回答、搜索摘要或非官方文章作为规则依据。
- 不解析新的客户文件格式，也不修改现有账套借贷平衡、Excel 安全读取或 Phase 2B 专业复核边界。
- 不让 AI 决定税种是否适用、选择税率或补造客户事实。

## 多宿主生态兼容

目标宿主包括 Codex、Hermes、WorkBuddy、扣子、Qoder、Claude Code 和 OpenClaw。兼容设计采用“一个核心、三种接入协议”，而不是维护七套税务实现：

1. **本地核心协议**：Python API、CLI 和稳定 JSON 模式是唯一业务真相来源。所有文件处理、规则选择、状态判断、确认校验和报告生成均在核心完成。
2. **Agent Skills 协议**：为支持本地命令和 Agent Skills 类规范的宿主提供薄说明层，负责安装检查、命令调用、中文追问顺序和结果展示，不包含税率或判断逻辑。
3. **MCP / HTTP 协议**：为不能直接安装或执行 Python 包的宿主提供薄服务层。它只映射核心输入输出，不改变状态、规则或审计记录。

初步路由为：Codex、Hermes、Qoder、Claude Code 和 OpenClaw 优先使用本地核心加 Agent Skills；扣子优先使用 MCP 或受控 HTTP；WorkBuddy 根据其宿主权限选择 Agent Skills、本地 CLI 或 MCP。正式实现前必须根据各平台当时的官方文档核验能力，不能依据平台名称猜测兼容性。

各适配器必须遵守以下共同契约：

- 客户问题和报告默认使用中文；
- 英文代码只在机器载荷和诊断接口中出现；
- 客户文件默认本地处理，远程传输必须由宿主明确披露并取得客户授权；
- 适配器不能构造确认、修改规则结果或把未解决状态改写成无风险；
- 同一输入、规则包版本和确认记录在各宿主上产生相同业务快照；
- 宿主不具备某项能力时必须明确提示，不得静默降级。

本阶段交付稳定核心契约、通用 Agent Skill 和适配器一致性测试夹具。需要独立部署、鉴权、租户隔离或公网服务的 MCP / HTTP 网关另行设计和实施；它不阻塞本地宿主使用全税种筛查。

## 产品边界

正式报告名称保持为《税务健康检查报告》。客户看到的状态为：

| 内部状态 | 客户文案 |
| --- | --- |
| `calculated` | 已完成计算 |
| `not_applicable` | 经资料确认不适用 |
| `needs_evidence` | 待补充资料 |
| `needs_local_policy` | 待确认当地政策 |
| `blocked` | 暂时无法判断 |

本阶段的 `screening` 规则包不会产生 `calculated`。当事实表明某税种可能适用时，在第三批计算规则完成前，结果保持 `needs_evidence`，并用中文说明尚需的申报、合同、计税基础或其他资料。只有证据充分的明确否定事实可以产生 `not_applicable`。

## 税费范围

全国筛查包覆盖：增值税、消费税、企业所得税、个人所得税、资源税、城市维护建设税、房产税、印花税、城镇土地使用税、土地增值税、车辆购置税、车船税、船舶吨税、耕地占用税、契税、烟叶税、环境保护税、关税，以及教育费附加、地方教育附加。

税种 ID 和中文名称继续由现有 `TAX_DEFINITIONS` 注册表控制。规则包不能自行增加未注册税种，也不能改变稳定 ID 的含义。

## 架构

### 1. 官方内置规则包

每个税费项目使用独立 JSON 清单，按税种、地区和生效期间版本化。全国包使用 `CN`；确有地方规则数据时才新增 `CN-NN` 包。规则选择仍遵循“精确地区优先、全国基线回退”，但缺失的地方参数不得从其他地区推断。

官方筛查包作为 Python package data 随 wheel 和 sdist 发布。宿主 Agent 只安装或升级 OpenTaxCheck，无需让客户理解或单独管理规则包。历史规则包不可原地改写；法规变化通过新增期间或版本明确的新包完成。

### 2. 中文事实词典

新增随包发布的版本化中文事实词典。规则包通过稳定 `fact_key` 引用词典，不重复保存客户文案。每个词典条目至少包含：

- 稳定事实键；
- 通俗中文问题；
- 必要的中文解释；
- 回答类型和允许选项；
- 可接受证据类型及中文示例；
- 客户不便回答时的下一步提示。

同一事实可以被多个税种引用，因此宿主 Agent 只问一次。例如，取得土地或房屋的业务事实可以同时服务于契税、印花税、房产税和土地使用税筛查。若多个规则包对同一事实要求不同回答类型、选项或证据语义，规则集加载失败，不能随机选择其中一种。

### 3. 审慎适用性门槛

每个筛查包声明一个或多个布尔型 `applicability_fact_keys`，代表客户能理解、可确认的业务事实，而不是抽象税法结论。例如问题应描述“是否购买过房屋或土地”，而不是要求客户判断“是否属于契税纳税人”。

通用筛查执行器采用以下固定语义：

- 任一适用性事实明确为真：该税种可能适用；本阶段输出 `needs_evidence`，并列出后续资料。
- 所有适用性事实明确为假，且每个否定均有客户确认审计引用或资料证据：输出 `not_applicable`。
- 任一必要事实未知：输出 `needs_evidence` 并生成中文问题。
- 必需地方参数缺失：输出 `needs_local_policy`。
- 同一事实存在未解决冲突、规则包损坏或执行结果不符合契约：输出 `blocked`。

不得仅因账套中“没有看到”某类交易而生成否定事实。AI 推断只能进入 `inferred` 状态；用于“不适用”的否定事实必须是可追溯的 `confirmed`，或来自明确证明该事实的结构化资料。

### 4. 规则包模式演进

现有 `1.0.0` prototype 清单保持可加载，以维持第一批兼容性，但默认选择继续排除 prototype。正式筛查包使用向前演进的模式，除现有标识、期间、成熟度、需求和来源字段外，增加：

- 规则数据版本；
- 中文事实词典版本；
- `applicability_fact_keys`；
- 适用时需要的资料事实；
- 可选的地方参数事实；
- 更完整的官方来源元数据。

`screening` 包使用同一个受控的通用筛查执行器，不为每个税种复制 Python 判断器。复杂税额计算和法定公式仍通过后续、单独审查的 `calculation` evaluator 实现。这样第二批的法规维护以 JSON 规则数据为主，同时避免引入可执行表达式、任意脚本或不安全 DSL。

## 官方来源

每个规则包至少包含一项与适用性门槛直接相关的官方依据。来源元数据包含：

- 发布机关；
- 文件标题和文号；
- 相关条款；
- 发布日期；
- 本项目核验日期；
- 官方 HTTPS 链接。

优先使用全国人大法律法规数据库、财政部、国家税务总局、海关总署及省级人民政府或税务机关的官方页面。GitHub 仓库和社区项目只可用于发现待核验场景，不能进入 `sources`。加载器验证字段结构和 URL 安全；发布验证另行检查 20 个项目是否都有官方依据，但不在客户运行时联网抓取网页。

## 客户运行流程

1. 宿主 Agent 安装包含官方筛查包的 OpenTaxCheck。
2. 客户提供账套、申报表、合同台账和其他资料。
3. 核心程序提取带来源引用的已观察事实；AI 可以协助解释，但不得把推断升级为客户确认。
4. 引擎按税种、地区和检查期间选择规则包。
5. 事实词典把缺口转为中文问题，并按事实键合并多个税种的重复提问。
6. 宿主 Agent 向客户提问，记录客户确认人、时间和证据引用。
7. 依赖图只重新运行受影响税种。
8. 报告立即更新中文状态、已用规则包、官方依据、资料缺口和限制说明。

客户正文不显示英文状态码、事实键、内部异常、文件系统路径或原始敏感值。机器可读 JSON 同时保留稳定英文代码与中文显示字段，供宿主 Agent 安全编排。

## AI 边界

AI 的职责是用中文解释资料要求、把确定性问题转换成更易懂的对话、协助定位客户可能拥有的资料，并把回答提交给严格验证的确认接口。AI 不得：

- 发明客户未确认的交易、身份或地区事实；
- 从非官方内容生成税率或地方参数；
- 绕过回答类型、证据引用或冲突检查；
- 把 `needs_evidence`、`needs_local_policy` 或 `blocked` 改写为“无风险”；
- 修改历史确认或规则包审计记录。

## 错误处理与安全

- 某一税种规则包失败只阻塞该税种，不清除其他税种结果。
- 2023–2026 任一期间未覆盖时，相关税种显示规则不可用，不得静默缩短检查期间。
- 相同税种、地区和期间的正式包重叠时，规则集整体发布验证失败。
- 地方参数缺失时保持 `needs_local_policy`，不得套用全国平均值或邻近地区数据。
- 客户事实冲突时保留全部安全证据引用，并保持 `blocked`，直到客户重新确认。
- 清单采用严格字段白名单、大小和数量上限；不加载任意模块名、脚本、模板表达式或网络资源。
- 对外诊断使用稳定代码，中文报告使用固定、无敏感内容的解释。

## 测试策略

每个税费项目至少提供明确适用、明确不适用和资料不足三类完全虚构的测试案例；声明了地方参数的项目还必须提供地方政策缺失案例。另需覆盖：

- “不适用”没有确认或证据时必须失败；
- 仅凭账套未发现交易不能判定不适用；
- 20 个规则包连续覆盖 2023-01-01 至 2026-12-31；
- 规则期间空档和重叠均被拒绝；
- 同一事实的词典定义冲突被拒绝；
- 多税种共享事实只生成一个中文问题；
- 客户确认只重跑受影响税种；
- 地方参数缺失不回退到其他地区；
- 规则包损坏只阻塞对应税种；
- 客户报告不泄露英文错误码、路径、原始敏感值或堆栈；
- 通用 Agent Skill 的模拟宿主测试覆盖安装检查、首次筛查、中文补问、客户确认、增量重跑和报告输出；
- 所有宿主适配器通过同一组 JSON 契约夹具，证明不会改变核心业务快照；
- 平台能力探测失败时明确报告“不支持”或“需要适配器”，不得假装执行成功；
- 源码、wheel、sdist 和隔离安装环境加载相同规则包并通过相同校验；
- 现有账套借贷平衡、Excel 安全读取、Phase 2B 与客户自用报告测试全部回归通过。

## 验收标准

1. 20 个税费项目都有默认可选的正式 `screening` 包，不再因缺少规则包而统一返回 `rule_pack_unavailable`。
2. 所有筛查包覆盖完整的 2023–2026 全国期间并包含合格官方来源。
3. 客户问题和报告正文均为通俗中文，机器接口保留稳定英文代码。
4. 没有明确确认或证据时，任何税种都不能生成 `not_applicable`。
5. 本阶段不产生 `calculated`，也不宣称完成税额计算。
6. 官方规则包随安装包分发，客户无需单独安装。
7. Codex、Hermes、WorkBuddy、扣子、Qoder、Claude Code 和 OpenClaw 均有明确的接入协议、能力边界和中文操作说明。
8. 全量源码与安装包测试通过；跳过或不可用的检查不得被表述为通过。

## 后续阶段

第三批另行设计计算与一致性规则，优先顺序为增值税、企业所得税、个人所得税、城市维护建设税及教育附加、印花税和契税。只有输入事实、官方参数和计算依据充分时才生成 `calculated`；第二批设计不提前实现这些公式。
