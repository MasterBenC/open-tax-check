## 1. 项目定位

OpenTaxCheck 是由个人发起、面向中国税务专业人士的开源 AI 税务健康检查工具。它通过确定性 Python 规则引擎、贯穿流程的 AI 税务助理和强制专业复核，提高税务风险检查的效率、可追溯性和交付质量。

项目完整开源。知识和基础规则不设置收费墙；项目的长期价值来自专业判断、真实项目协作、复杂税收争议解决能力及持续运营的税务伙伴网络。

项目商业与社区闭环为：

```text
开源工具
→ 税务师、会计师和企业使用
→ 公开知识讨论及微信社群
→ 共同完善规则、测试与案例
→ 发现复杂税收争议
→ 发起人组织跨专业协作
→ 争议解决、专项顾问和项目合作
```

## 3. 首发范围

首发目标是一个可用于真实专业流程的完整版本，而非只有演示价值的 Alpha。

### 3.1 产品形态

- 完整 Skill：供 WorkBuddy、OpenClaw 及其他支持 Skill 和文件操作的 Agent 使用。
- 独立 Python CLI：供技术人员、本地自动化和无 Agent 环境使用。
- 首发不包含独立网页或桌面界面；该界面属于后续版本。

### 3.2 企业和期间范围

- 中国境内居民企业，单一法律实体为一个案件。
- 增值税一般纳税人与小规模纳税人。
- 规则基线覆盖 2024、2025、2026 税务年度。
- 首发覆盖商贸、服务、软件科技、建筑设计和一般制造业。
- 房地产、金融、保险、证券、烟草、石油等特殊行业通过后续行业规则包扩展。
- 默认分析期为最近 24 个月，并允许案件配置其他期间。

### 3.3 输入资料

- Excel、CSV；
- 可复制文字的 PDF；
- 扫描 PDF 和常见图片格式；
- 压缩包内的受支持文件；
- 科目余额表、序时账、申报表、完税证明、发票汇总、合同和其他税务证据材料。

## 4. 核心设计原则

1. 薄 Skill、厚 Python：Agent 负责交互和智能工作，Python 负责确定性底座。
2. AI 深度参与但不越权：AI 是全流程税务项目助理，税务师拥有正式结论和发布权。
3. 算术、阈值、勾稽、状态、版本和数据血缘由代码控制。
4. 未确认字段映射、阻塞性数据质量问题和缺失关键证据不得静默绕过。
5. 没有检查或证据不足不能表述为没有风险。
6. 所有正式发现必须可追溯到来源文件、页码、单元格、行号、凭证号、规则和版本。
7. 系统结果、AI 分析和人工专业结论分层保存，不相互覆盖。
8. 流程可中断、可恢复、可重复运行，并复用已确认的 OCR、映射和 AI 结果。
9. 报告是税务咨询与风险筛查成果，不是审计、鉴证、法律意见、申报结论或税务机关认定。

## 5. 系统架构

### 5.1 Agent 适配层

- 接收资料、说明进度、提出必要问题并展示下一步行动。
- 将 Python 生成的结构化 AI 任务交给宿主模型执行。
- 将模型输出写回统一结果 Schema，再交给 Python 校验。
- 能力较弱的宿主只运行较小、边界清晰、可验证的任务。

### 5.2 资料接收和解析层

- 保存原始文件并建立文件清单、哈希、期间和资料类型。
- Excel/CSV 直接读取单元格和结构，不做 OCR。
- 数字 PDF 优先提取原始文字、表格坐标和页码。
- 扫描 PDF/图片进入 OCR 流程。
- 无法识别、重复、损坏或疑似错误期间的文件形成明确异常记录。

### 5.3 OCR 适配层

采用三级方案：

1. 本地 PP-OCRv6：普通扫描件和简单票据的默认文字识别引擎。
2. 本地可用的 PaddleOCR-VL/PP-Structure：复杂表格、合同和报表的隐私优先解析。
3. 百度 PaddleOCR-VL-1.6 API：严重变形、复杂版式、印章、疑难表格的授权云端增强。

云端调用必须获得用户明确授权，可以按文件或页面选择。所有引擎统一输出 OCR Schema，包含引擎、版本、页码、坐标、置信度、原图引用和提取时间。金额、税号和日期优先采用双引擎或账务勾稽验证。

### 5.4 标准数据层

- 将不同来源字段映射为统一 Schema。
- 同时保留原始值、标准值、清洗规则、映射依据和映射版本。
- AI 可以提出映射建议；Python 检查必需字段、类型和一致性；低置信度映射由人工确认。

### 5.5 数据质量和勾稽层

- 凭证借贷平衡；
- 余额表期初、发生额和期末勾稽；
- 总账、明细账、申报表之间的核对；
- 期间完整性、重复数据、币种、符号和异常格式检查；
- 关键质量问题形成阻塞状态并给出解决动作。

### 5.6 规则与计算层

- Python 执行税率、阈值、公式、账龄、跨期和勾稽计算。
- 规则根据企业画像、期间、纳税人类型、税种和可用资料路由。
- 规则结果保留适用版本、计算输入、公式、结果、证据和未满足条件。

### 5.7 AI 税务助理层

AI 参与：

- 资料分类、缺失资料识别和资料补充清单；
- 字段映射建议和客户自定义科目理解；
- 风险规则路由和不适用可能性分析；
- 凭证摘要、科目、对方单位、合同、发票和付款路径的深度语义审计；
- 规则库之外的新风险假设；
- 跨文件支持证据、反向证据和缺失证据分析；
- 客户访谈问题及补充资料后的重新评估；
- 适用期间官方法规研究和引用草稿；
- 初审、复核差异总结和结论完整性检查；
- 管理层摘要、财务整改步骤和技术附件草拟；
- 报告公司名称、期间、数字、引用和前后结论一致性检查。

AI 不能静默修改原始数据、公式、适用期间、正式规则或专业结论。

### 5.8 专业复核和报告层

- 税务师在 Excel 工作底稿中确认、排除或调整风险事项。
- 专业结论状态包括 `suspected`、`confirmed`、`closed` 和 `insufficient_data`。
- 报告引擎只接受已完成复核且批准进入报告的事项。
- DOCX 是可编辑母版，PDF 是客户版固定交付物。

### 5.9 外部信息适配层

- 风鸟企业查询通过用户自己的 `FN_API_KEY` 运行。
- 百度 OCR、大模型和其他外部服务均采用环境变量或宿主安全凭证，不进入仓库。
- 外部服务不可用时不影响确定性账套检查。

## 6. AI 运行模式

- `off`：纯 Python；适合保密环境、无模型环境和确定性复核。
- `assist`：默认模式；执行映射建议、语义筛查、资料追问、证据整理和报告草拟。
- `deep`：执行跨文件推理、法规研究、反向证据分析、多轮客户补充和复核辅助。

### 6.1 Agent 托管模式

Python 将 AI 任务写为结构化作业；WorkBuddy/OpenClaw 使用自身模型执行；Python 校验返回结果的 Schema、证据定位、引用和数字完整性。

### 6.2 独立 CLI 模式

独立运行时通过 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL` 接入兼容服务。本项目不绑定具体大模型厂商，也不保存用户密钥。

## 7. 模块化规则库

### 7.1 通用核心规则包

- 企业所得税；
- 增值税及附加；
- 个人所得税；
- 印花税；
- 发票与凭证；
- 社保公积金；
- 关联交易；
- 对外支付与代扣代缴。

### 7.2 扩展规则包

- 行业规则包；
- 地区执行口径包；
- 历史期间规则包。

### 7.3 规则 Schema

每条规则必须包含：唯一编号、税种、名称、适用期间、适用纳税人、所需数据、前置质量条件、触发条件、排除条件、Python 计算函数、AI 分析任务、支持与反向证据、官方依据、默认风险等级、常见误报、专业复核问题、测试案例、规则版本和修改记录。

### 7.4 规则类型

- 确定性规则：Python 完成金额、比例、账龄和勾稽计算。
- 混合规则：Python 缩小样本，AI 分析语义和证据，输出候选。
- 专业判断规则：AI 整理事实和不同解释，税务师作出判断。

### 7.5 规则生命周期

```text
草拟
→ 法规依据核对
→ 专业人员审核
→ 测试数据验证
→ 正式发布
→ 更新或停用
```

AI 可以发现法规变化并生成更新建议，但不能直接修改正式规则。公式、阈值、适用期间和结论边界发生变化时必须增加规则版本并通过回归测试。

## 8. 用户工作流和案件状态

```text
创建案件
→ 上传资料
→ AI 自动分类和资料清单
→ 本地解析/OCR
→ 必要时申请云 OCR 授权
→ 字段映射与人工确认
→ 数据质量和勾稽检查
→ 企业信息补充
→ 硬规则计算
→ AI 深度风险分析
→ 自动生成资料追问
→ 客户补充材料
→ AI 重新评估
→ 税务师复核工作底稿
→ 生成 DOCX 与 PDF
→ 数字、引用和视觉质量检查
→ 正式交付
```

关键状态至少包括：等待资料、等待映射确认、数据质量阻塞、等待云端授权、等待客户补充、等待专业复核、等待报告批准、已完成和运行失败。每个状态必须给出 `next_action`。

重复运行不覆盖原始结果；同一输入和规则版本应产生相同的确定性结果。案件状态和中间产物支持断点续跑。

## 9. 四件套交付物

### 9.1 `workpaper.xlsx`

包含项目控制、资料清单、OCR 与映射复核、数据质量、硬规则、AI 候选、证据、风险复核、涉税测算、客户问题、报告选取及编制复核记录。每项发现可以跳转至来源。

### 9.2 `report.docx`

可编辑专业报告母版，供税务师修改、评论和复核。报告内容由结构化结果渲染，AI 不直接控制最终版式。

### 9.3 `report.pdf`

客户版报告包括：封面和保密声明、目的和范围、资料覆盖、执行摘要、风险分布、重大风险、一般提示、整改路线图、待确认事项、方法论和法规附件。

每个重大事项固定展示：风险标题、等级和状态、账面事实、系统计算、AI 分析与其他解释、支持与反向证据、缺失资料、适用法规、潜在影响、专业结论、整改建议和资料索引。

视觉系统采用独立设计的董事会简报风格：深蓝主色、青色辅助、红黄风险提示、一页一个重大事项、数字卡片、图表和整改时间线。不得复制任何专业机构商标或受保护模板。PDF 必须逐页渲染检查。

### 9.4 `evidence-pack/`

保存标准化数据、OCR JSON、风险 JSON、规则版本、法规来源、AI 作业与结果、证据索引和运行日志。该包主要用于内部复核和结果解释，不默认全部交给客户。

## 10. 安装和依赖分层

```text
open-tax-check[core]     Excel/CSV、规则引擎、JSON
open-tax-check[ocr]      PDF、图片、本地 OCR
open-tax-check[report]   Excel 底稿、DOCX、PDF
open-tax-check[ai]       独立 CLI 大模型接口
open-tax-check[full]     完整安装
```

首发为 Windows、macOS 和 Linux 提供安装说明及自动测试。重量级 OCR 和报告依赖不强制安装到只需要核心规则的环境。

## 11. 安全、隐私和数据治理

- 默认本地处理，不收集遥测信息。
- 不向 OpenTaxCheck 项目方上传客户资料。
- 调用百度 OCR、外部模型或企业查询前明确提示服务、数据范围和授权状态。
- 密钥仅存在于环境变量或宿主安全凭证。
- 输出文件清理不必要的作者、路径和自定义元数据。
- 日志默认掩码税号、身份证号、银行账号和其他敏感标识。
- 提供案件加密、脱敏和安全删除指引。
- GitHub Issue、Discussion 和示例中禁止真实客户资料。
- 示例企业、账套、合同、发票、申报表和报告全部虚构。
- 安全漏洞和敏感信息通过 `SECURITY.md` 指定的私下渠道报告。
